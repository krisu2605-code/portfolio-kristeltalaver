VaultContext is not a tutorial project. It's a read-only calendar conflict detector I designed, shipped, and keep running in production — OAuth 2.0, push-notification webhooks, a Postgres database, and deterministic timestamp logic that replaced an unreliable AI prototype.

The point of building it wasn't the feature list. It was proving I can design a system, diagnose it when it fails in ways a demo never would, and make the judgment calls — what to build, what to defer, and what to cut.

Selected debugging

Four failures, traced to root cause

Each one is real, verified live, and recorded in git history. The method was the same every time: reproduce it, read the evidence, fix the actual cause — or decide it isn't worth fixing.

INCIDENT · 01 RESOLVED

I was wrong about my own logic

SymptomA real 15-min overlap was mislabeled as a harmless Gap: 0 min.
TraceMy tests only ever used overlaps > 30 min, so they never hit the broken branch. I doubted logic I'd already shipped and documented as correct.
CauseA threshold split — overlapMinutes >= 30 — routed small overlaps into the wrong tier. Fixed structurally so the branch can't recur.
INCIDENT · 02 RESOLVED

The failure that happened before my code ran

SymptomA request failed, but the server logs were completely silent.
TraceSilence was the clue — no log line meant the request never reached the server. Command-line tests passed because they aren't browsers.
CauseA cross-origin preflight the server wasn't answering. "No error in the logs" meant the failure happened before my code ever ran.
INCIDENT · 03 RESOLVED

The phantom 24-hour event

SymptomNormal meetings flagged as overlapping a full 24-hour block that didn't exist.
TraceAll-day events arrive from Google as a bare date, not a timestamp — parsed as midnight UTC, which in UTC+7 stretched into a phantom day-long span.
CauseA timezone parsing defect affecting every non-local user. Filtered all-day events at the source — a product decision, not a patch.
INCIDENT · 04 SCOPED OUT

The write that silently did nothing

SymptomA wired-up button did nothing on click — no change, no error shown.
TraceThe write returned 204 No Content but changed zero rows; tightening security made it 42501. Decoded the live token, verified ownership in SQL — every layer matched.
CauseReproduced the rejection in pure SQL — a row-level-security interaction, not my front-end. Then cut the feature: it was redundant, and knowing when to stop is part of the job.
Decisions I can defend

Judgment over knowledge

AI supplied syntax I didn't have. Every architectural decision, verification, and trade-off was mine.

SAFETY

Read-only on purpose

The system suggests and confirms; it never edits a user's calendar. A bug sends a wrong email, not a corrupted schedule. Auto-reschedule is a deliberate, deferred next step.

RELIABILITY

Math, not a language model

Whether two events overlap is arithmetic — it must be exact every time. I use AI for knowledge I lack, never for a runtime decision that has to be right. That line was drawn deliberately.

DURABILITY

Documented over clever

I chose Google's stable template URL over an undocumented trick that could edit directly. Built to still work in a year, not just to demo today.
